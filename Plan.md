# Execution Plan: MLOps Deployment Learning Project

## Goal
Learn deployment and MLOps on GCP. A model change in git ends up serving traffic safely, with monitoring and rollback. ML quality is irrelevant. All time goes to infra.

## Ground rules
1. Data is synthetic and tiny (5k to 20k rows), generated by `src/make_data.py` with a fixed seed.
2. Models are trivial: logistic regression (classification) and a T-learner (uplift).
3. Test locally with Docker Compose before deploying to the cloud.
4. Batch cloud time per phase. Tear down expensive resources after each session.
5. Stay on the Free Trial account. Never upgrade billing.
6. Repeat the full build from `terraform destroy` to deployed at least twice.

## Architecture
Synthetic CSV to GCS, then BigQuery `raw`, then Dataform to `staging` and `features`. Two Vertex custom training jobs write models to Model Registry. Each model is served from a custom container on a Vertex Endpoint. A facade FastAPI on GKE Autopilot calls both endpoints and returns `{p_convert, uplift, recommendation, degraded}`. Requests are logged to BigQuery for drift checks.

## Phase 0: Foundation (day 1)
1. Create the project and budget alert. Apply the Terraform in `infra/`.
2. Use the Makefile targets: `init`, `plan`, `apply`, `destroy`.

Done when: `make apply` and `make destroy` both run cleanly.

## Phase 1: Data and ELT (days 2 to 3)
1. Write `src/make_data.py`: treatment flag, features, label, known true uplift, flags `--shuffle-labels` and `--shift-features`.
2. Upload the CSV to GCS, load into `raw` unchanged.
3. Dataform builds `staging`, `features`, `train`, `test` with assertions (nulls, treatment balance).
4. Schedule with Workflows and Cloud Scheduler.

Done when: a scheduled run rebuilds all tables and a failed assertion stops the run.

## Phase 2: Training as jobs (days 4 to 5)
1. `train_clf.py` and `train_uplift.py` read from BigQuery and write artifacts to GCS.
2. One training image, run both as Vertex Custom Jobs with the `ml-trainer` service account.
3. Log AUC and Qini to Vertex Experiments. Register models with aliases `candidate` and `champion`.

Done when: both jobs run from the CLI with no notebook.

## Phase 3: Serving (days 6 to 7)
1. FastAPI serving container per model with `/predict` and `/health`.
2. Test with Docker Compose locally first.
3. Build with Cloud Build, deploy to Vertex Endpoints on the smallest machine.
4. Log requests and responses to `serving_logs` in BigQuery.

Done when: `curl` to each endpoint returns predictions and log rows appear.

## Phase 4: Facade on GKE Autopilot (days 8 to 10)
1. Facade calls both endpoints in parallel with timeouts. Fallback: if uplift fails, return classification only.
2. Deployment, Service, Gateway, Workload Identity, resource requests, HPA, probes.
3. Kustomize overlays `dev` and `prod`.
4. Load test with `hey` or `locust` and watch the HPA.

Done when: a public URL returns the combined response and survives a pod kill under load.

## Phase 5: CI/CD (days 11 to 12)
1. GitHub Actions with Workload Identity Federation, no key files.
2. Pull request: lint, unit tests, image build, local container smoke test.
3. Merge: push images, deploy facade, roll back on failed probes.
4. Tighten the `cicd` service account roles.

Done when: merging a change deploys with zero manual steps.

## Phase 6: Vertex Pipelines (days 13 to 14)
1. KFP pipeline: data check, train both, evaluate, register as `candidate` only if metrics beat `champion`.
2. Trigger from Cloud Scheduler and manually. Enable caching.

Done when: a model trained with `--shuffle-labels` is rejected automatically.

## Phase 7: Release safety and monitoring (days 15 to 16)
1. Canary via endpoint traffic split (10 percent, then 100 percent). Practice rollback.
2. Vertex Model Monitoring for skew and drift. Cloud Monitoring dashboard for latency, errors, request count.
3. Alerts for p95 latency, 5xx rate, drift.
4. Send data made with `--shift-features` and confirm the drift alert fires.

Done when: promote and rollback of a model version takes under 5 minutes.

## Phase 8: Close the loop (day 17)
1. Drift alert triggers the retraining pipeline.
2. README with architecture diagram, runbook, cost notes.
3. `make teardown`.

## Cost guardrails
1. Undeploy endpoints and delete the cluster after every session.
2. No GPUs, no Composer, smallest machine types, one region.
3. Watch the Billing overview page for credit and days remaining.

## Known waits (plan around them)
Endpoint deploy 10 to 15 minutes. Training job startup a few minutes. GKE cluster creation and first pod several minutes.
